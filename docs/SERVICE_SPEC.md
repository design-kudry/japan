# Полная функциональная спецификация Travelapp

Дата среза: **17.11.2026**. Документ описывает текущую реализацию основной веб-версии. Источник проверки — код, а не прежние обещания или отдельные макеты. Этот документ заменяет противоречащие ему старые записи в документации.

Макеты: [Figma](https://www.figma.com/design/aUQnGXZkcguG0Sow8bTp1h/Untitled). Основная поверхность — React SPA в `index.html`; сохранённые старые HTML-страницы перечислены отдельно в разделе 18.

## 1. Назначение и границы продукта

Travelapp помогает собрать поездку, выбрать достопримечательности, распределить их по дням, сохранить перемещения, расходы и заметки. Одна установленная копия приложения обслуживает несколько локальных поездок.

Приложение статическое. Пользовательские данные находятся в браузере; серверной базы поездок, совместного редактирования и синхронизации между устройствами нет. Доступ к размещённому сайту может ограничиваться авторизацией хостинга; это не пользовательский аккаунт внутри планировщика.

| Возможность | Текущее состояние |
| --- | --- |
| Создание поездки с датами или количеством дней | Работает |
| Несколько городов, изменение порядка, переключение поездок | Работает |
| Маршрут по дням, сворачивание секций, конструктор и карта | Работает |
| Каталог стран и городов, категории, стоимость, избранное | Работает; полнота зависит от источников |
| Общая библиотека мест, поиск, описания и фотографии | Работает; часть данных загружается через сеть |
| Ручные бронирования и сегменты, билеты как вложения | Работает локально |
| Онлайн-поиск рейса, распознавание билета, статусы и push | Не подключено; есть клиентский контракт будущего API |
| Добавление расходов, список, баланс и график | Работает с ограничениями раздела 11 |
| Создание, редактирование и удаление заметок | Работает |
| «Поделиться» | Передаёт URL, не данные локальной поездки |
| Облачная копия, импорт/экспорт всей поездки, пространства | В основном интерфейсе не реализованы |

## 2. Навигация

| Адрес / вход | Экран и поведение |
| --- | --- |
| `#new` | Создание поездки |
| `#japan` | Встроенная поездка «Япония» |
| `#trip/<id>` | Созданная пользователем поездка |
| `<поездка>/places` | «Места» |
| `<поездка>/expenses` | «Расходы» |
| `<поездка>/notes` | «Заметки» |
| `#cities/<id>` | Существующий редактор городов и дат; старый HTML-интерфейс |
| Название поездки в шапке | Нижняя шторка переключения поездок |
| «Редактировать маршрут» | Конструктор текущего дня |
| «Настройки» в нижней навигации | Меню действий: города и даты, если доступны; перемещение; удаление поездки |

`#trips` и неизвестный адрес перенаправляют в последнюю допустимую поездку. Если встроенная Япония удалена, выбирается оставшаяся поездка либо создание новой. Отдельная современная главная со списком карточек поездок не является самостоятельным работающим экраном: список доступен в переключателе.

Нижняя навигация закреплена: «Маршрут», «Места», «Расходы», «Заметки», «Настройки». Переключение меняет hash внутри приложения. При смене поездки выбранный день сбрасывается; последний активный маршрут запоминается в браузере.

## 3. Поездки

### 3.1. Создание

1. Открыть «Добавить поездку» в переключателе.
2. Выбрать «Точные даты» или «Количество дней».
3. В режиме дат выбрать начало и конец. Поле изначально пустое. Диапазон включает оба крайних дня.
4. В режиме количества ввести целое число от 1 до 366. Поле пустое; без числовых стрелок.
5. Ввести город и выбрать конкретный вариант из подсказок. Страна берётся из выбранного варианта.
6. При необходимости добавить другие города, включая города других стран.
7. Нажать «Добавить». После успешного сохранения открывается маршрут созданной поездки.

Одинаковая пара «город + страна» не добавляется повторно. Нельзя создать поездку без города, с невалидным периодом или продолжительностью более 366 дней. Название созданной поездки формируется из уникальных названий её городов; отдельного поля произвольного названия в форме нет.

Если городов несколько, у них доступны ручка сортировки и удаление. В форме нельзя удалить единственный выбранный город отдельной кнопкой. Перестановка городов не означает автоматическое распределение достопримечательностей по дням.

### 3.2. Даты и города после создания

Для поездки с календарными датами меню «Города и даты» открывает существующий HTML-редактор. Он позволяет менять порядок городов, добавлять города и задавать необязательные периоды городов в границах поездки. У дня отображаются города, чей заданный период включает эту дату.

Поездка без дат имеет ключи дней `day-1`, `day-2` и т. д. В интерфейсе показываются номера дней. Перевод уже созданной поездки из количества дней в календарные даты в текущем интерфейсе не реализован. Автоматической миграции назначений мест и перемещений при смене календаря нет.

### 3.3. Переключение

В нижней шторке перечислены встроенная Япония, если не удалена, и созданные поездки. В карточке доступны название, период и изображение, если оно найдено у мест поездки. Выбор текущей поездки только закрывает шторку; выбор другой открывает её маршрут. Внизу есть «Добавить поездку».

### 3.4. Удаление

«Настройки» → «Удалить поездку» → подтверждение. Созданная поездка исключается из массива поездок. Для встроенной Японии записывается `japanDeleted`. После успешного удаления открывается следующая допустимая поездка или создание новой.

Отмены удаления через интерфейс нет. Отдельные ключи расходов и заметок, а также файлы билетов не очищаются каскадно при удалении всей поездки: это ограничение хранения, а не гарантированное удаление всех связанных данных.

### 3.5. «Поделиться»

Сначала используется системная передача ссылки через Web Share API. Если API недоступен или завершился ошибкой, приложение пытается скопировать URL; если это невозможно, показывает поле для ручного копирования. Отмена системного диалога не считается ошибкой.

Передаётся только URL текущего маршрута. У получателя нет локального объекта созданной поездки, поэтому ссылка не является механизмом приглашения, копирования маршрута или совместной работы.

## 4. Страница маршрута

Маршрут отображает все дни поездки. Каждый день содержит заголовок, мини-карту доступных координат, сегменты перемещений, старые переезды при их наличии и упорядоченные карточки мест. Во встроенной Японии также используются исходные данные о проживании.

- В начальном состоянии секции дней раскрыты.
- Заголовок сворачивает или раскрывает соответствующую секцию.
- Полоса дней в шапке прокручивает к выбранному дню; прокрутка маршрута обновляет выбранный день.
- В пустом дне показывается «Вы пока ничего не добавили».
- Нажатие на место открывает полную карточку.
- Нажатие на сегмент открывает всё бронирование, которому он принадлежит.
- Разворачивание мини-карты открывает отдельную карту выбранного дня.
- Ссылка Google Maps строит внешний маршрут по координатам; внутренний планировщик не получает из неё дорожную геометрию.

На отдельной карте маршрута используются только точки выбранного дня, их номера и линия. Нет поиска новых мест и редактирования порядка. Это не режим отображения маршрутов всех дней одновременно.

Между соседними секциями дней — **16 px** независимо от сочетания раскрытых и свёрнутых состояний.

## 5. Конструктор маршрута

### 5.1. Вход и сохранение

«Редактировать маршрут» открывает текущий день. Список мест, нижний расчёт времени и действия находятся в шторке поверх карты. Переключение дня внутри конструктора меняет редактируемый список.

Изменение порядка, удаление и оптимизация сохраняются сразу, без общей кнопки «Сохранить». Закрытие конструктора не отменяет ранее сохранённые изменения. При ошибке сохранения показывается сообщение, последнее корректное состояние не должно заменяться неуспешной записью.

### 5.2. Состояния шторки

| Состояние | Вид и действия |
| --- | --- |
| `full` | Список занимает доступную область под верхней панелью; есть кнопка «Карта»; ручка скрыта |
| `half` | Карта и список одновременно; высоту можно оставить в промежуточном положении |
| `peek` | У нижнего края остаётся ручка, контент списка скрыт |
| `browse` | Расписание скрыто, поверх карты открыты карточки выбранных мест |

На входе используется `full`, если не задан сценарий открытия карты/точки. Кнопка «Карта» переводит к промежуточному виду. При перетаскивании действуют привязки у верхней и нижней границ; в середине сохраняется свободная высота. Нажатие на ручку переключает предустановленные положения. Нижний футер остаётся закреплённым.

### 5.3. Работа с местами

- Перетаскивание за ручку меняет порядок мест текущего дня. Поддержаны Pointer Events и клавиатурные стрелки на ручке.
- Корзина удаляет место из маршрута; это не удаление из общей библиотеки и не автоматическое удаление из избранного.
- Нажатие на строку открывает полную карточку.
- «Добавить место» открывает общий каталог.
- «Добавить перемещение» открывает транспортный сценарий из раздела 10.
- Последняя карточка и «Добавить место» разделены **20 px**. Пустой контейнер бронирований не занимает место.
- Между кнопками «Добавить место» и «Добавить перемещение» — **12 px**.

В основном конструкторе нет отдельной кнопки ручного создания произвольного места по адресу, ссылке или координатам. Такие формы остались только в старом коде.

### 5.4. Назначение дня

В полной карточке можно выбрать день и добавить место. Если оно назначено на другой день, действие переносит его; если уже назначено на выбранный — предлагает убрать. Повторное добавление того же ID в один день отклоняется.

В мини-карточке конструктора действие относится к текущему дню. После успешного добавления закрываются поиск/карточка, очищается запрос и открывается нужный день. В зависимости от входа возвращается полный или промежуточный список. Ошибка сохранения не должна выглядеть как успешное добавление.

Избранное и назначение дня — разные состояния. Само добавление через текущий `schedulePlace` не записывает новое место в `wishlist`. Подпись «В маршруте» на карточках не показывается; доступные действия учитывают назначение.

### 5.5. Оптимизация и длительность

«Оптимизировать» доступно при наличии не менее трёх мест с координатами. Первый такой объект сохраняется начальным; остальные выбираются последовательно по близости к предыдущему. Элементы без координат сохраняют свои позиции.

Это эвристика ближайшего соседа, без дорожного API, расписаний, часов работы, пробок и гарантии самого короткого пути.

Длительность маршрута: расстояния между соседними доступными координатами делятся на 75 м/мин, затем добавляются распознанные длительности посещений. В диапазоне длительности используется первое найденное число. Нулевое/нерассчитанное значение выводится как тире. Это ориентировочная пешая оценка, не расчёт перевозчика.

## 6. Каталог «Места» и «Добавить место»

Оба входа используют `AddPlaceCatalog`: общие фильтры, окна выбора, группировку, карточки и подгрузку. Отличаются оболочкой и способом возврата к родительскому экрану.

### 6.1. Содержимое и группировка

1. Начальный выбор стран берётся из городов поездки.
2. Сразу показываются готовые авторские места известных городов.
3. Справочник городов расширяется городами страны, не ограничиваясь поездкой.
4. Авторские направления дополняются подготовленными файлами GeoNames в `places/cities/<ISO>.json`.
5. Секции городов содержат горизонтальные ленты; вход в конкретный город открывает сетку.
6. «Все места» и «Хочу посетить» переключают общий каталог и сохранённые записи текущей поездки.
7. В обычном каталоге готовые подборки первичны; их не задерживают ответы внешних источников.

Для города с готовыми местами текущая ветка загрузки показывает готовую подборку и не обязана дополнительно вызывать внешний поиск достопримечательностей этого города. Наличие большого справочника городов не означает наличие большой подборки в каждом городе.

### 6.2. Фильтры

| Элемент | Поведение |
| --- | --- |
| Сортировка | Включает/выключает алфавитный порядок секций городов |
| Страна | Окно с поиском и множественным выбором стран; «Применить» подтверждает черновик |
| Крестик страны | Снимает выбранные страны и текущий город; не сбрасывает стоимость или категорию |
| Чем заняться | Окно выбора одной категории либо «Все» |
| Стоимость | Окно выбора «Бесплатно», «Платно» либо «Все» |
| Крестик активного фильтра | Сбрасывает только этот фильтр; соседние фильтры остаются |
| Отмена в окне | Закрывает окно, не применяя черновик |

Категории: «Музеи и галереи», «Храмы и соборы», «Парки и природа», «Памятники и архитектура», «Смотровые», «Парки развлечений», «Другие места». Категория определяется по нормализованному типу и, при необходимости, ключевым словам.

«Стоимость» проверяет исходную строку цены. Отсутствующая цена не доказывает бесплатность. В текущем коде платность определяется непустой строкой, которая не распознана как бесплатная; значения наподобие `~` могут классифицироваться неточно. Это ограничение реализации фильтра.

Секции без подходящих карточек скрываются после завершения загрузки; загружающиеся секции сохраняют скелетоны. Для пустого результата есть текстовое состояние. При выборе конкретного пустого города показывается его пустое состояние.

После сброса стран экран группируется по странам и показывает известные места общей библиотеки и стартовые направления. Это не полный мировой каталог. Клик по стране раскрывает её городские секции; клик по городу открывает места города. Отдельного множественного выбора городов в текущем общем каталоге нет.

### 6.3. Подгрузка и ошибки

Дополнительные города загружаются порциями по 24; приближение к нижнему краю запускает следующую порцию через IntersectionObserver. Кнопки «Загрузить места» нет. Загрузка городов выполняется ограниченной очередью; карточки появляются по готовности.

Имеющиеся карточки не заменяются общей ошибкой или пустым экраном при отказе дополнительного источника. На время загрузки карточек и медиа используются скелетоны. После ошибки фотографии остаётся статичная заглушка. Сообщение «Не удалось загрузить остальные города» в основном виде убрано. Ошибка конкретной пустой подборки может показывать повтор; автоматическая подгрузка не гарантирует бесконечное повторение неуспешных запросов.

Заголовок, категории и фильтры в обоих списках прокручиваются с контентом. Сведения о GeoNames находятся в раскрываемом разделе «Источники данных», а не постоянной подписи поверх каталога.

## 7. Общий поиск мест и городов

Один `RoutePlaceSearch` используется в каталоге, конструкторе и на карте.

- В покое отображается TextInput с лупой и подсказкой «Найти место».
- Город и выбранный объект не подставляются в поле автоматически.
- Поиск начинается с введённого символа; запрос к источникам выполняется после паузы около 350 мс.
- Источники: известные локальные места, Photon, Open-Meteo для городов, русская Wikipedia.
- Результаты объединяются по идентичности. Сетевой поиск отдаёт до 12 результатов; интерфейс с локальным дополнением — до 16.
- Географический контекст влияет на ранжирование, но поиск не ограничен городами поездки.
- Существуют состояния «Поиск…», «Ничего не найдено» и ошибка поиска.
- Новый запрос/закрытие отменяет устаревшую работу, где используется AbortController.
- Стрелки клавиатуры перемещают фокус по результатам. Escape и «Отмена» закрывают поиск.

Выбор города перемещает карту к городу и не создаёт достопримечательность в маршруте. Выбор места из полного списка конструктора открывает описание; выбор из карты центрирует точку и открывает мини-карточки. Возврат из описания без добавления может восстановить запрос; успешное добавление очищает его.

Переход к общему поиску использует View Transitions, если API поддержан и пользователь не запросил reduced-motion. Отсутствие анимационного API не должно блокировать сам поиск.

## 8. Библиотека и карточки мест

### 8.1. Идентичность и качество

Каталог, карта, избранное и маршрут используют общие записи через `place-library.js`.

Приоритет сопоставления: ID, Wikidata ID, затем нормализованное имя с проверкой близости координат. При объединении сохраняются авторская идентичность и приоритет готовых текстов. Это клиентская библиотека, а не серверный глобальный каталог.

Одна карточка описывает одно место. Два отдельных объекта не объединяются только потому, что находятся рядом или исторически связаны. Одноимённые удалённые объекты не считаются одинаковыми. Подгрузка метаданных не меняет ID, название и координаты выбранной карточки. Полная карточка открывается для того же объекта, который отображён в маршруте. Ближайшая статья без совпадения названия не используется вместо места; библиотека отклоняет совпадение ID с далёкими координатами. Исторические исходные записи всё ещё могут содержать неточности; автоматическое сопоставление не заменяет проверку координат.

Автоматические рекомендации отбираются строже явного поиска: требуются подходящий туристический тип, связанная статья/Wikidata, фото и содержательный русский текст. Для авторских/подготовленных записей есть отдельный приоритет. Кафе, рестораны, магазины, гостиницы, продуктовые и торговые рынки исключаются фильтром достопримечательностей. Существующие пользовательские маршруты не должны очищаться только из-за ужесточения автоматического отбора.

### 8.2. Маленькая карточка каталога

Фото, сердце, название, краткое описание и строка метаданных. Фото имеет зарезервированную область даже при загрузке/ошибке. Длинный текст ограничивается CSS и многоточием.

Пагинации и стрелок поверх маленькой карточки каталога нет. Свайп фотографий сохраняется, когда доступны дополнительные снимки. Нажатие на фото маленькой карточки сейчас открывает полное описание, а не отдельный PhotoViewer.

### 8.3. Мини-карточка карты / конструктора

Фото высотой 166 px; белая часть перекрывает его на 20 px. Внутри — название, читаемое краткое описание и метаданные. На карте доступно избранное; в конструкторе дополнительно есть действие для текущего дня. Стрелок листания фотографий внутри карточки нет.

При нескольких снимках показываются точки пагинации: диаметр 8 px, промежуток 4 px, 32 px на три точки. Точки стоят на 9 px выше белого блока. Свайп по фото не должен перелистывать соседние карточки мест или открывать описание после завершения жеста.

### 8.4. Полное описание

Содержит фото, возврат, избранное, название, полное описание короткими абзацами и доступные поля:

- «Время работы»;
- «Билет», если есть отображаемая цена;
- «На посещение», если заполнена длительность.

Краткие и полные описания начинаются с заглавной буквы; в полном тексте правило применяется к абзацам. Регистр внутри названий и остального текста не меняется целиком.

При наличии источников показываются ссылки текста, медиа и метаданных. При наличии дней поездки внизу доступны выбор дня и действие добавления/переноса/удаления. В просмотре карты маршрута нижнее назначение дня может быть скрыто.

### 8.5. Цена и часы

Отображение выполняют `placeMeta` и `placeRouteMeta`; исходные строки сохраняются.

| Данные | Отображение |
| --- | --- |
| Одна распознаваемая цена | `≈` + сумма и валюта |
| Бесплатный вход, распознанный из строки | «Бесплатно» |
| Платно без известной суммы, неоднозначные тарифы | Числовая цена не выдумывается |
| Обычный диапазон часов | Короткий диапазон, без сезонных и тарифных пояснений в маленькой карточке |
| Круглосуточный доступ | «Круглосуточно» |
| Часы не распознаны | «Уточнить часы» |

В компактной карточке цена и часы — одна строка через `·`, с обрезкой при переполнении. Текущая реализация `placeRouteMeta` использует первый распознанный диапазон часов. Для типов quarter/neighbourhood/neighborhood/suburb/monument/memorial и флага outdoorAlwaysOpen код показывает «Круглосуточно» без цены. Такая классификация сама по себе не является внешней проверкой реального доступа.

Полная карточка выводит источник метаданных, если он есть; текст «Уточнить часы» не гарантирует отдельную кликабельную ссылку на официальный сайт в каждом случае.

### 8.6. Фотографии и полноэкранный просмотр

Основное фото и до шести отобранных дополнительных файлов поступают из связанных статей/Commons. Дополнительные снимки допускаются при наличии ссылки на источник и лицензии; карта, логотипы, флаги и другие явно неподходящие файлы отсекаются эвристикой. Дубликаты обложки и вариантов одного источника объединяются.

Если источник вернул один снимок, приложение показывает один: дополнительные кадры не придумываются. Галереи видимых карточек запрашиваются с ограничением параллельности. Проверка лицензии не гарантирует, что автоматический отбор никогда не ошибётся в содержании кадра.

Нажатие на фото в полной карточке открывает отдельный `PhotoViewer` поверх описания:

- видимый крестик справа сверху;
- стрелки по сторонам при нескольких снимках;
- переключение горизонтальным свайпом/перетаскиванием и клавишами ←/→;
- точки пагинации;
- Escape или крестик закрывает только фото и возвращает в описание;
- выбранный индекс синхронизирован с обложкой полной карточки;
- при наличии данных отображаются авторство, лицензия и ссылка.

Пользовательская загрузка иллюстраций достопримечательностей в текущем основном интерфейсе не предусмотрена. Билет-вложение — отдельный транспортный сценарий.

## 9. Карты

### 9.1. Источники и режимы

Основная карта — MapLibre GL и OpenFreeMap. При недоступности WebGL/инициализации используется Leaflet с растровой картой OSM. Для подложек и внешних данных нужна сеть. Атрибуция поставщиков сохраняется.

| Режим | Точки и поведение |
| --- | --- |
| Каталог / карта мест | Известные места, точки текущей области и выбранный результат; без номеров маршрута |
| Конструктор | Места текущего дня, избранное, известная библиотека внутри области и внешние рекомендации; маршрутные точки могут быть пронумерованы |
| Развёрнутая карта маршрута дня | Только места дня, номера и линия; без внешней подборки |

Внешняя выборка области использует общий `placesInBounds`: сначала известные локальные места, затем географические результаты Wikipedia RU/EN с приведением к русской записи и фильтрацией. В актуальном пути этой функции Photon не является источником выборки области. При масштабе ниже 5 возвращается локальный слой; полный список всех мировых объектов не загружается. Публикуемый результат ограничен 120 местами области.

После ручного перемещения карта обновляет рекомендации с небольшой задержкой. Программное перемещение к соседней карточке не должно постоянно перестраивать ленту. Нажатие на свободную карту закрывает выбранную карточку; в конструкторе возвращается расписание.

Если карточка открыта из маршрута, перелистываются места этого маршрута дня. Для карточек, открытых из области, используется сформированный набор мест области. Смена карточки подсвечивает/центрирует соответствующую точку.

### 9.2. Компонент точки

Для полноэкранных карт и карты конструктора используется Map/Map-module из Figma 327:14415 / 327:14411:

- фотографический круг 36 px, рамка 2 px;
- обычная рамка белая, выбранная чёрная;
- избранное — красная рамка `#d10000` и красный бейдж с сердцем;
- для маршрутной точки сохраняется номер; номер занимает позицию бейджа;
- подпись справа, отступ 6 px, шрифт 13/15, максимум 120 px и две строки;
- географический якорь остаётся в центре круга, а не всего блока с подписью;
- при пересечении скрываются второстепенные подписи; выбранная получает приоритет;
- отсутствие фото сохраняет круг с заглушкой, а не вымышленное изображение.

Маркеры хранятся по ID и обновляются без пересоздания всей карты. Мини-карта внутри дня показывает фон OpenStreetMap, номера и связи точек в общей географической проекции. При изменении ширины карты фон и точки пересчитываются вместе; тайлы загружаются лениво.

В редакторе одновременно показаны места и связи всех дней поездки. У каждого дня постоянный цвет; выбранный день выделен толщиной и насыщенностью линии. Карта открывается на местах выбранного дня. Между разными днями соединение не строится. Несохранённые изменения текущего сеанса сразу учитываются на карте. Дополнительной легенды и переключателей нет.

## 10. Передвижения и билеты

### 10.1. Модель и вход

Trip содержит Booking[], Booking содержит Segment[]. Бронирование — заказ целиком; сегмент — одна часть пути. Пересадка — промежуток между соседними сегментами одного заказа, рассчитываемый при отображении.

Вход: «Добавить перемещение» в конструкторе или меню настроек. Кнопка конструктора — контурная Gravity Button xl с Car 20 px.

На первом экране транспорт не выбран. Доступны самолёт, автобус, поезд, паром. Только после явного выбора появляется «Способ добавления»:

- «По номеру рейса» — только для самолёта;
- «Загрузить билет»;
- «Ввести вручную».

«По маршруту» в интерфейсе отсутствует. У выбранного транспорта одна чёрная рамка, без второго selection-контура.

### 10.2. Ручное добавление

Для каждого сегмента: транспорт, перевозчик, номер, отправление и прибытие — название пункта, код, локальная дата/время и часовой пояс; дополнительные место, класс, терминал, гейт/платформа. Для поездки без календарных дат выбирается день маршрута.

Общие поля бронирования: поставщик/где куплен билет, PNR, пассажиры текстом, стоимость всего заказа, валюта, файл билета. Валюты текущего выбора: RUB, GBP, EUR, USD, JPY, KZT, CNY, AED. Это не конвертация валют.

«Добавить пересадку» создаёт следующий сегмент с исходным пунктом предыдущего прибытия; можно удалить лишний сегмент, оставив минимум один. Перед сохранением есть просмотр карточек и явное подтверждение «Добавить»/«Сохранить».

### 10.3. Валидация

- Не менее одного сегмента и допустимый тип транспорта.
- Названия отправления и прибытия обязательны.
- Валидные локальные даты/время и часовые пояса.
- Прибытие позже отправления после перевода в UTC.
- Следующий сегмент не отправляется раньше предыдущего прибытия.
- При заданной стоимости — конечное неотрицательное число; ноль допустим.
- День отправления входит в поездку; для режима без дат используется назначенный `day-N`.
- Неоднозначное или отсутствующее местное время при переходе DST требует уточнения; молчаливого выбора одного смещения нет.

Перевозчик, PNR и коды не проверяются по внешнему справочнику. Формат IATA/номера не доказывает существование рейса. Пассажиры не являются отдельными пользовательскими аккаунтами.

### 10.4. Просмотр, редактирование и удаление

В дне показываются сегменты по локальной дате отправления или assignedDay. Карточка содержит перевозчика/вид транспорта, номер, даты, время, пункты и вычисленную длительность. Между соседними отображаемыми сегментами выводится пересадка; при разных кодах возможна пометка о смене станции/аэропорта.

Нажатие открывает бронирование целиком. Доступны редактирование всех его сегментов, сохранение и удаление с подтверждением. Закрытие изменённого черновика запрашивает отказ от несохранённых изменений. Длительность и пересадка не хранятся как самостоятельные поля.

При редактировании сохраняются ID бронирования и существующих сегментов, createdAt; updatedAt обновляется. Статус по умолчанию — unknown. Данные статуса в модели не означают проверку перевозчиком; отдельный селектор ручного статуса сейчас скрыт.

### 10.5. Билет

Принимается один файл PDF, JPEG, PNG или WebP размером до 20 MiB. В текущем сценарии загрузка означает прикрепление, а не распознавание содержимого. Файл записывается в IndexedDB только при окончательном сохранении бронирования; метаданные и ID файла находятся в Booking.sourceFile.

Из просмотра можно скачать прикреплённый файл. Он доступен только в том браузере и на том origin, где был записан. При замене после успешной записи удаляется прежний файл; при удалении бронирования выполняется попытка удаления файла. Байтам билета не соответствует облачная постоянная ссылка.

### 10.6. Неподключённые интеграции

Поле рейса — Gravity TextInput xl с лупой и подсказкой «Номер рейса»; дата выбирается компонентом DatePicker. Без конфигурации сервера поиск недоступен и предлагается ручной ввод.

`TransportProvider` содержит будущий контракт:

| POST endpoint | Вход | Ожидаемый результат |
| --- | --- | --- |
| `/flights/lookup` | number, date | segments |
| `/journeys/search` | kind, from, to, date | segments |
| `/tickets/extract` | multipart file | Черновик полей бронирования и сегментов |
| `/segments/verify` | segments | verified и данные проверки |

Endpoint не реализован одним наличием адаптера. AeroDataBox, AirLabs, Cirium, Amadeus, Duffel, Omio и другие провайдеры не подключены. Нет OCR, PDF text extraction, декодирования BCBP/PDF417/Aztec, LLM-разбора, фоновой проверки статусов или push. Ключи будущих провайдеров должны оставаться на сервере.

## 11. Расходы

### 11.1. Основные ограничения

Расходы относятся к отдельной поездке и хранятся в её ключе localStorage. Текущий модуль использует **JPY** и фиксированных участников **«Вика» и «Женя»** для всех поездок. Это работающий ограниченный модуль, не универсальная мультивалютная бухгалтерия.

При отсутствии локальных данных у встроенной Японии показываются исходные демонстрационные записи. У новой поездки список пустой. Расходы не создаются автоматически из цены Booking.

### 11.2. Создание

«Добавить расход» открывает форму: название, положительная целая сумма в иенах, плательщик, дата, категория и участники равного разделения. По умолчанию выбраны оба участника, дата — локальная текущая.

Категории: «Покупки», «Рестораны и бары», «Транспорт», «Продукты», «Другое», «Без категории», «Развлечения».

Нельзя сохранить пустое название, неположительную/нецелую/небезопасно большую сумму или расход без участников. После успешного сохранения открывается список, очищается поиск и сбрасывается режим добавления. Отмена формы не создаёт запись.

### 11.3. Список

Записи сортируются по дате от новых к старым и группируются по дням. Для дня выводится сумма, для записи — название, плательщик и сумма. «Мои расходы» — всё оплаченное первым участником; «Общие расходы» — сумма всех записей. Эти итоги не ограничиваются поисковой строкой.

Поиск расходов доступен из меню и фильтрует названия. Если есть исходный план расходов, меню может показать/скрыть его отдельно. Редактирование и удаление отдельной записи, управление участниками и категориями в текущем UI не реализованы.

### 11.4. Кошелёк

Баланс участника = сумма оплаченных им расходов − сумма его долей. Доля каждого выбранного участника равна amount / количеству участников разделения. Положительный баланс — участник заплатил больше своей доли; отрицательный — меньше. Фактический перевод денег и отметка погашения долга не выполняются.

### 11.5. График

Круговая диаграмма и суммы по категориям. Периоды: месяц, год, всё. Для месяца/года выбираются доступные значения из записей. При нулевой сумме нет искусственной заполненной диаграммы. Конвертации, курсов валют, банковских интеграций и выгрузки отчёта нет.

## 12. Заметки

Отдельный список заметок поездки. Можно создать, открыть, изменить заголовок/текст, сохранить и удалить заметку. Хранятся id, title, text.

Поле текста — простой textarea: без rich text, вложений, папок и совместного редактирования. Пустые заголовок и текст вместе не сохраняются; если текст есть, а заголовок пуст, используется «Без названия». Сохранение выполняется явной кнопкой. Закрытие редактора не является автосохранением. Удаление заметки выполняется сразу, без отдельного подтверждения.

| localStorage `places-v2:<страна\|город>` | Кеш сетевой городской подборки с временем записи; в коде срок 24 часа |
| IndexedDB `travel-ticket-files`, store `files` | Байты билетов по sourceFile.id |
| Память вкладки | Библиотека загруженных мест, кеши источников и галерей, черновики, состояние фильтров/окон |

Trip: id, start/end либо dateMode=days + dayCount, cities[], places[], wishlist[], routeEdits, transfers[] старого формата, bookings[]. Часть массивов и полей создаётся лениво.

Встроенная Япония объединяет исходные DAYS/STAYS с локальными изменениями. Её bookings и routeEdits находятся в корневом сохранённом объекте, а не в отдельной записи trips[].

Place: стабильный id; name/nameEn при наличии; lat/lng; city/country/category; shortDesc/desc; hours/price/duration; img/imageOriginal и поля авторства/лицензии; wikidata/wiki и ссылки источников. Полнота зависит от записи. ID: wd:Q…, osm:…, wiki:… либо резервный name|lat|lng.

Booking: id, tripId, supplier, pnr, passengers, price|null, currency, sourceFile|null, segments[], createdAt, updatedAt.

Segment: id, kind, carrier, number, from/to {name, code, timeZone}, departureUtc, arrivalUtc, status, seat, travelClass, terminal, gate; assignedDay для бездатного маршрута. В форме присутствуют departureLocal/arrivalLocal как поля черновика; расчёт выполняется по UTC.

Очистка браузера, другой профиль, origin или устройство не сохраняют доступ к локальным данным. Код GitHub не содержит пользовательские изменения из localStorage. Нет фонового экспорта и восстановления из облака.

## 14. Источники и внешние подключения

| Источник | Реальная роль |
| --- | --- |
| Авторские каталоги Японии и Великобритании | Готовые записи, описания и координаты; приоритет перед внешними текстами |
| Подготовленные JSON GeoNames | Города выбранной страны; не автоматическое наличие достопримечательностей каждого города |
| Open-Meteo Geocoding | Поиск/координаты городов |
| Photon | Глобальный поиск объектов и городов |
| Wikipedia RU/EN, Wikidata | Поиск/географические кандидаты, идентичность, русские статьи, страна объекта, описания |
| Wikimedia Commons | Фотографии и сведения о лицензии/авторстве |
| OSM element API, Overpass | Теги точных объектов, часы и платность |
| Wikivoyage, ограниченные подготовленные записи метаданных | Дополнительные часы/цены при сопоставлении объекта |
| OpenFreeMap / OSM / растровые поставщики fallback | Подложки карты |
| Google Maps | Внешняя ссылка просмотра/маршрута; не источник внутреннего расчёта |

Публичные источники не гарантируют актуальность цены и режима работы, полноту выдачи и непрерывную доступность. Ошибки сети не должны превращаться в придуманные данные. Подборка города проверяет страну по Wikidata P17; произвольная точка карты определяется областью, а не текущим фильтром страны.

## 15. Общие правила интерфейса

Gravity UI UIKit, Gravity Date Components, Gravity Icons; основной шрифт Inter. Основная React-поверхность сейчас принудительно использует светлую тему. Переключателя тем нет.

| Элемент | Правило |
| --- | --- |
| Секции дней маршрута | 16 px между соседними секциями во всех состояниях |
| Карточки/строки конструктора → «Добавить место» | 20 px |
| «Добавить место» → «Добавить перемещение» | 12 px |
| Фото мини-карточки карты | 166 px по высоте |
| Перекрытие фото белым блоком | 20 px в мини-карточке, 24 px в полной |
| Пагинация | Точки 8 px, промежутки 4 px; на 9 px выше белого блока |
| Маркер полной карты | 36 px, рамка 2 px |
| Поисковое поле | Gravity TextInput с лупой 16 px |

Шапки/фильтры каталогов не закрепляются при прокрутке. Шапка маршрута, нижняя навигация и футер конструктора закрепляются в своих сценариях. Учитываются safe-area и видимая высота viewport; поведение физической экранной клавиатуры требует проверки на целевом устройстве.

Кнопки ⋮ в шапке конструктора временно скрыты; это не означает отсутствия всех меню сервиса — меню расходов и настроек существуют.

## 16. Ошибки и сохранность

- Отсутствующие данные показываются как пустое состояние, скелетон или заглушка согласно сценарию, а не случайный контент.
- Неудачный сетевой запрос может дать частичную выдачу; готовые карточки остаются.
- Ошибки сохранения поездки, маршрута, избранного, бронирования, расходов и заметок должны быть видимы в соответствующем интерфейсе.
- Сохранение вложения не завершает бронирование, если запись метаданных не удалась; созданный в этой попытке файл очищается.
- Потерянный билет не восстанавливается из Booking.sourceFile: там только метаданные. Предлагается прикрепить файл повторно.
- Название страны/города и координаты источника могут иметь ошибки; единая библиотека не является гарантией их абсолютной точности.
- Состояния загрузки/фото не должны сбрасывать выбранные фильтры или менять порядок пользовательского маршрута.

## 17. Что не считать реализованным

Помимо ограничений отдельных разделов, нет: авторизации пользователей самого приложения, ролей и приглашений; пространств; облачной синхронизации; универсального экспорта/импорта; гарантированной офлайн-карты; календарной миграции бездатных поездок; автоматической покупки билетов; реального времени транспорта; LLM-генерации описаний; универсальной мультивалютности; универсального менеджмента проживания.

Файл `planner-sw.js` завершает работу старого offline-кеша и снимает прежнюю регистрацию Service Worker. Это не современный offline-first режим.

## 18. Legacy и обратная совместимость

В репозитории сохранены japan.html, places/*.html, shops.html, expenses.html, tokyo-builder.html, tokyo-test.html и старые JS-модули. Некоторые адреса старого формата перенаправляются к ним. В `trips.js` остались формы собственного места, простых переездов и старого каталога. Их наличие в коде не означает доступность соответствующей кнопки в новой React-поверхности.

Действующий редактор `#cities/<id>` всё ещё использует HTML-реализацию. Встроенные исходные проживание/плановые расходы Японии — подготовленные данные, а не новые универсальные CRUD-модули.

## 19. Проверка изменений

Это критерии приёмки; список не утверждает, что все пункты автоматически протестированы в каждом коммите.

1. Создание с пустыми полями, валидными датами, количеством дней 1 и 366, ошибочным 0/367; города и перестановка.
2. Переключение поездок, разделов и сохранение после перезагрузки.
3. Раскрытые/свёрнутые дни: отступ 16 px для всех сочетаний.
4. Конструктор: reorder, удаление, перенос дня, сохранение; отступы 20/12 px.
5. Шторка full/half/peek/browse, возврат от карточки и клавиатурный доступ.
6. Каталог обоих входов: страны, категории, стоимость, независимые крестики, пустые состояния, подгрузка без кнопки.
7. Поиск: пустая строка, ввод, город/место, отмена, ошибки, возврат запроса.
8. Единая запись места в каталоге, карте, избранном и маршруте; отсутствие подписи «В маршруте».
9. Фото: загрузка/ошибка, одна и несколько фотографий, точки над перекрытием, свайп, полноэкранные стрелки, крестик/Escape и синхронизация индекса.
10. Карта: маркеры обычный/выбранный/избранный, координатный якорь, подписи; карта дня без посторонних рекомендаций.
11. Бронирование: один/несколько сегментов, разные зоны, ночной перелёт, DST, неверная последовательность, редактирование, отмена черновика, удаление, файл.
12. Расходы: обязательные поля, равные доли, список/поиск, кошелёк, график; заметки: сохранение/редактирование/удаление.
13. Узкий экран, скролл, видимость кнопок закрытия и нижних действий.

Сборка: `npm ci`, затем `npm run build`; результат `dist/`. Прямые проверки модулей: `node --test tests/photo-gallery.test.mjs tests/transport.test.mjs`. Для тестов с импортами, требующими браузерной сборки, сначала используется esbuild по примерам в файлах тестов. Наличие отдельных проходящих проверок не означает прохождение всего исторического набора.
