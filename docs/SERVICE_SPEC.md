# Спецификация сервиса Travelapp

Клиентский планировщик поездок без бэкенда. Данные только в `localStorage` текущего браузера. UI — React 18 + Gravity UI; карта — MapLibre (OpenFreeMap) с запасным Leaflet/OSM.

## Запуск

```sh
npm ci
npm run build
npx serve dist
```

Открыть URL сервера. Основные hash-маршруты: `/#japan`, `/#new`, `/#trip/<id>`, `/#trip/<id>/places|expenses|notes`.

## Карта экранов

| Hash | Экран | Что делает |
|---|---|---|
| `#new` | Создание поездки | Даты или число дней, города, страна |
| `#japan` / `#trip/<id>` | Маршрут | Дни, мини-карта, карточки мест, FAB → конструктор |
| `…/places` | Места | Каталог страны, «Хочу посетить», карта области, поиск |
| `…/expenses` | Расходы | Список, балансы, график |
| `…/notes` | Заметки | Локальные заметки поездки |
| `#cities/<id>` | Legacy HTML | Старый редактор городов/дат |

Встроенная поездка «Япония» питается из `js/data.js` (DAYS, STAYS, EXTRA_PLACES). Остальные поездки — пользовательские объекты + живые источники мест.

## Модель данных

Ключи `localStorage`:

- `japan-travel-trips-v1` — `{ trips[], japanTransfers[], japanPlaces[], japanWishlist[], japanDeleted?, routeEdits? }`
- `japan-active-trip` — последний hash активной поездки
- `travel-notes-v1:<routeHref>` — заметки
- `trip-expenses:<routeHref>` — расходы

Поездка пользователя: `{ id, start, end | dateMode:'days'+dayCount, cities[], transfers[], places[], wishlist[], routeEdits }`.

Идентификатор места: `place.id` или `name|lat|lng`. Источники id: `osm:…`, `wd:Q…`, `wiki:…`, `city:…`.

## Конструктор и шторка

Компонент `RouteExplorer` (`js/gravity-trips.jsx`).

### Режимы `data-sheet`

| Режим | Позиция Y | Chrome |
|---|---|---|
| `full` | ≈ 68px (под шапкой) | Список на весь экран, кнопка «Карта», **ручки нет** |
| `half` | свободная высота между магнитами | Карта + расписание, ползунок виден |
| `peek` | только полоска ручки над футером | Контент шторки скрыт CSS |
| `browse` | шторка спрятана | Мини-карточки мест на карте |

Вход в конструктор → `full`. «Карта» → `half` (ползунок появляется). В середине высоту можно оставить. Почти у верха (~24% хода) — магнит в `full` и снова «Карта»; у низа — магнит в `peek`. Во время drag chrome = `half`, чтобы контент не мигал. Тап по ручке циклит preset.

Шапка поиска: везде подпись и placeholder **«Найти место»**; без автоподстановки города. Query только из ввода пользователя.

### Геометрия (JS ↔ CSS)

- `full` offset и отступ карты/поиска: **68px**
- высота шторки: `calc(100% - 68px - var(--constructor-footer-space))`
- `--constructor-footer-space` ≈ `56px + safe-area`

Менять эти числа нужно синхронно в `RouteExplorer.offsets` и `css/gravity-trips.css`.

## Места: как работает сейчас

### Вкладка «Места»

1. Страна активной поездки → `countryPlaces()` (`js/country-places.js`).
2. Быстрый слой: геокод городов + Wikipedia geosearch; позже музеи / World Heritage.
3. Принадлежность стране — Wikidata P17; чужие объекты отбрасываются.
4. Фон: `enrichPlaces()` для первых ~20 (фото, часы, цена).
5. Фильтры: города поездки, тип; «Хочу посетить» — wishlist с теми же фильтрами.

### Карта мест / карта конструктора

1. После паузы pan (`PlacesMap` ~220ms, конструктор ~180–280ms) → `placesInBounds()`.
2. Сейчас: **1** Photon-запрос по центру + Wikipedia EN/RU geosearch, clip по bbox.
3. Масштаб < 10 или слишком большой bbox — запрос не идёт.
4. Результаты с кириллицей в имени показываются в конструкторе; обогащение фоном.

### Поиск

Согласовано 12.11.2026 (Figma 302:29545):
- В любой вкладке, в списке конструктора и на карте пустой поиск показывает «Найти место». Город и название выбранного объекта автоматически не подставляются.
- Подпись — Inter Regular 15 px / 20 px, цвет `--g-color-text-hint` (30% чёрного). Это placeholder, а не значение поля.
- Нажатие плавно раскрывает общий поиск. Пользователь вводит запрос, выбирает результат и открывает карточку. «Отмена» плавно возвращает к предыдущему экрану.
- После успешного добавления места в маршрут запрос очищается; снова показывается «Найти место». При ошибке добавления запрос сохраняется.
- Закрытие карточки без добавления в конструкторе возвращает к введённому запросу.
- Кнопки меню с тремя точками временно скрыты во всём сервисе. Для них нет интерактивной области и места в раскладке.


`usePlaceSearch` / `searchWorld`: Photon + Open-Meteo (города) + RU Wikipedia. Debounce ~350ms. Кафе/отели отфильтрованы (`isAttraction`).

### Карточка места

Полное описание: фото/заглушка, текст и метаданные по единым правилам `docs/place-meta.md` (согласовано 12.11.2026). Для подтверждённого уличного объекта со свободным доступом — только «Круглосуточно». Для остальных — реальные часы и известная цена платного входа. Цена содержит только сумму и валюту; бесплатный вход не подписывается. Если часы неизвестны — «Уточнить часы» со ссылкой на подтверждённый официальный сайт; без сайта — обычный текст. Категория не даёт оснований автоматически назначить 24/7 или бесплатный вход. Эти правила применяются во всех представлениях карточек. Поле «На посещение» не показывается. Источники фото/текста — ссылки Wikipedia/Commons. Форматирование реализовано общими функциями `placeMeta` / `placeRouteMeta`; в компактных карточках «Уточнить часы» открывает полную карточку, где доступна ссылка на официальный сайт.

### Обогащение

`enrichPlaces` (`js/place-enrichment.js`): Wikipedia/Commons/Wikidata для медиа; OSM API 0.6 и Overpass для часов/цены. Таймаут fetch ~12s, кеш патчей в памяти. Для Японии часы могут прийти из статики `js/place-hours.js`.

## Карта

1. Попытка MapLibre + стиль OpenFreeMap Positron (`/js/maplibre-worker.mjs`).
2. При ошибке WebGL/конструктора — Leaflet + OSM растр.
3. Маркеры стабильны по `placeId`; declutter ~46px на экране «Мест».
4. В режиме маршрута: номера + линия; точки области полупрозрачны.

## Внешние API (без ключей)

| Источник | Назначение |
|---|---|
| OpenFreeMap / OSM | Подложка |
| Photon | Поиск и выборка области |
| Open-Meteo Geocoding | Города |
| Wikipedia / Wikidata / Commons | Каталог, фото, описания |
| OSM API / Overpass | Часы, цена |

При сбое источника — частичный результат или сообщение; вымышленные места/фото не подставляются.
