# Передвижения

Макеты: Figma aUQnGXZkcguG0Sow8bTp1h, секция 321:9173.

## Работает

- Trip → Booking[] → Segment[]. Существующие поездки сохраняются; старые transfers не перезаписываются.
- Добавление из конструктора и меню настроек. Самолёт, автобус, поезд, паром.
- Ручной ввод, предварительный просмотр, подтверждение, открытие, редактирование Booking и его Segment, удаление с подтверждением.
- Booking: id, tripId, supplier, pnr, passengers, price (весь заказ), currency, sourceFile, createdAt, updatedAt.
- Segment: id, kind, carrier, number, from/to (name, code, timeZone), departureUtc, arrivalUtc, status, seat, travelClass, terminal, gate. Ввод — местное время. Даты в UTC — источник для расчётов. assignedDay используется для поездок без календарных дат.
- Длительность и пересадка рассчитываются, не хранятся. Проверяется порядок времени, включая ночные рейсы и разные часовые пояса. Неоднозначное и отсутствующее время при DST требует уточнения.
- Статус по умолчанию unknown («Не проверен»). Ручной статус не означает проверку перевозчиком.
- Бронирование и сегменты сохраняются в существующем localStorage поездок. PDF/изображения до 20 МБ — в IndexedDB. Прикрепление сохраняется только после подтверждения. Отмена не создаёт заказ. Файлы доступны только в этом браузере на этом устройстве; синхронизации и облачного хранения нет.
- Карточки по макету: перевозчик и номер, даты, время, пункты, продолжительность; полные данные внутри. Один Segment — одна карточка. Все сегменты одного заказа редактируются вместе.

## Не подключено (не выдавать за работающую функциональность)

Поиск по рейсу и маршруту, OCR/PDF text/BCBP + LLM, внешняя проверка статуса, облачное хранение билетов, фоновые проверки и push. Существующий сайт статический; в этой версии нет серверного API, ключей провайдеров, очереди фоновых задач или push-подписки. В интерфейсе поиск явно недоступен, предлагается ручной ввод. Загрузка файла сейчас означает прикрепление, а не распознавание.

## Контракт сменных провайдеров

`TransportProvider` в js/transport-providers.js — клиентская граница к будущему серверу. Сервер выбирает конкретного поставщика независимо от UI. Ключи только на сервере.

- POST /flights/lookup: {number,date} → {segments: Segment[]}.
- POST /journeys/search: {kind,from,to,date} → {segments: Segment[]}.
- POST /tickets/extract: multipart file → поля Booking + Segment[]. Сервер должен хранить исходный файл, извлекать PDF текст / OCR, декодировать BCBP при наличии, получать JSON по схеме и возвращать черновик.
- POST /segments/verify: {segments} → {verified:boolean,segments?:Segment[]}.
- Автоимпорт никогда не сохраняет Booking: пользователь проверяет черновик и подтверждает.

Нельзя задавать TRANSPORT_API_BASE, пока эти endpoint не реализованы. Это адаптерный контракт, не готовая интеграция с AeroDataBox, Amadeus и другими сервисами. Фоновые статусы и push требуют отдельной серверной реализации и разрешения браузера.
