# Как сейчас подтягиваются места

Живая схема «как есть». Меняем этот документ вместе с логикой — сначала договорились, потом код.

Стек без Google: **Photon**, **Wikipedia / Wikidata / Commons**, **Open-Meteo** (города), **OSM / Overpass** (часы/цена). Общий таймаут fetch ≈ **12 с**.

```
                    ┌─────────────┐
                    │  UI экран   │
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
    список страны    карта области     поиск строкой
    countryPlaces    placesInBounds    searchWorld
           │               │               │
           └───────────────┴───────┬───────┘
                                   ▼
                            enrichPlaces
                     фото → часы/цена (фон)
```

---

## 1. Вкладка «Места» (список)

**Где:** `PlacesView` ← `travel-pages.jsx`, данные страны из `trips.js`.

| | Япония (`#japan`) | Другая поездка |
|---|---|---|
| Старт | Каталог из `data.js` (DAYS + EXTRA) уже на экране | Пустой список / лоадер |
| Сеть | Всё равно зовётся `countryPlaces('Япония')` и **домешивается** | Только `countryPlaces(страна)` |

**`countryPlaces` (`country-places.js`):**

1. Страна → Q-id Wikidata (через RU Wikipedia).
2. **Быстро, параллельно:** до 3 городов поездки (Open-Meteo + wiki geosearch), поиск «город + достопримечательности», «страна + landmarks».
3. Каждый батч: `isAttraction` → проверка **P17 = эта страна** → RU имя → `onUpdate` (список растёт).
4. Потолок **80** мест; кеш в памяти `страна|города`.
5. Позже: музеи / World Heritage.
6. Фон: `enrichPlaces` только для **первых 20** (фото/часы).

**Фильтры UI:** города поездки, тип места. Сегмент «Хочу посетить» — только wishlist из `localStorage`, **без** сети.

---

## 2. Карта во вкладке «Места»

**Где:** `PlacesMap` → после паузы pan **220 ms** → `placesInBounds(bounds)`.

**`placesInBounds` (`world-places.js`):**

- Не ищет, если zoom **&lt; 10** или область слишком большая.
- Сейчас: **1× Photon** по центру + Wikipedia geosearch **EN + RU** по bbox.
- `isAttraction`, обрезка по границам, кеш bbox (~40 ключей).
- На карте ещё фильтр **кириллицы в имени** (как и nearby в конструкторе).

Пины = места из списка + ответ области + выбранная карточка. Enrich по видимым osm/wiki точкам — фоном.

**Режим маршрута дня** (`routeMode`): внешних запросов **нет**, только точки этого дня.

---

## 3. Конструктор (редактировать маршрут)

**Шторка full:** nearby **не** грузится (`mode === 'full'`).

**После «Карта»** (half / peek / browse): bounds → debounce **280 ms** (browse **180 ms**) → тот же `placesInBounds` → кириллица → `setNearby` → `enrichPlaces`.

На карте вместе: места **дня** + **wishlist** + **nearby**. Клик по пину → browse + мини-карточки.

Список дня в шторке отдельно: `enrichPlaces` по местам дня (часы/цена в secondary line).

---

## 4. Поиск (конструктор и Места)

**Где:** `RoutePlaceSearch` + `usePlaceSearch` → debounce **~350 ms** → `searchWorld`.

**`searchWorld`:** Photon + Open-Meteo (города) + RU Wikipedia search → кириллица → город или достопримечательность → топ **~12**, потом enrich.

Плюс локальный оверлей: уже известные места поездки/каталога/wishlist в выдаче.

---

## 5. Карточка места (detail / preview)

При открытии: `enrichPlaces([place])`.

Порядок внутри enrich:

1. Фото (Wikipedia / Commons / Wikidata P18) — сразу emit  
2. OSM API по `osm:…` id — часы / fee  
3. Overpass (Wikidata или around+name) — часы  
4. Кеш патча 2–8 мин  

Текст: `polishDescription` / teaser категории (`russian.js`) — без выдуманных фактов.

---

## 6. Что считается «достопримечательностью»

`isAttraction` (`world-places.js`): туристические/исторические теги и wiki landmark; **кафе / отели / магазины отсекаются**.

Дополнительно почти везде: **имя с кириллицей** (из‑за этого EN-only точки пропадают).

В каталоге страны ещё жёстче: только объекты с Wikidata **P17 = страна поездки**.

---

## 7. Где болит (для совместной переработки)

1. **Три разных входа** (страна / bbox / строка) без общего PlaceStore — одни и те же id качаются снова.  
2. **Кириллический фильтр** режет нормальные места за рубежом.  
3. **Япония:** каталог + всё равно live `countryPlaces` — дубль и шум.  
4. **Описания** из wiki часто «про что это в энциклопедии», не «зачем идти» → идея LLM в [BACKLOG.md](./BACKLOG.md).  
5. Нет единого контракта «что такое Place на экране» (обязательные поля, когда показывать скелетон).

## Черновик целевой модели (ещё не код)

Предложение на обсуждение — можно править прямо здесь:

| Слой | Ответственность |
|---|---|
| **Discovery** | Найти кандидатов (страна / область / query) |
| **Identity** | Один `placeId` (wd: / osm: / wiki:) + merge |
| **Present** | Имя, фото, teaser, часы, цена для UI |
| **Cache** | Общий inflight + TTL; позже серверный LLM-кеш |

Правило показа: сначала то, что уже есть локально → сеть discovery → enrich/LLM только для открытой карточки или первых N в списке.
