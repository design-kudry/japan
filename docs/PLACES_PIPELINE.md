# Библиотека, каталог, поиск и карта мест

Срез кода: 17.11.2026. Этот файл заменяет прежнее описание трёх несвязанных каталогов. Полное поведение UI — [SERVICE_SPEC.md](SERVICE_SPEC.md), разделы 6–9.

## 1. Общая запись

place-library.js объединяет подготовленные каталоги Японии/Великобритании и записи, найденные в текущей вкладке. libraryPlace возвращает приоритетную запись; registerPlaces пополняет память и сообщает place-library-updated. Идентичность: ID, Wikidata, затем нормализованное имя с близкими координатами. mergePlaces объединяет дубли, сохраняя приоритетные тексты и найденные медиа.

Это клиентский слой, не серверная БД. Он не даёт безусловной гарантии отсутствия ошибок сопоставления. Одна карточка должна описывать одно реальное место; соседство объектов не повод объединять их.

## 2. Каталог

AddPlaceCatalog используется обоими входами. Начальные страны берутся из поездки. seedPlaces выдаёт известные места города с авторским порядком guideOrder.

Текущий загрузчик при наличии seed-мест сразу показывает их и завершает эту ветку загрузки города; внешнее расширение каждого такого города не гарантировано. Для остальных вызывается cityPlaces.

Города: авторские направления + подготовленные /places/cities/<ISO>.json на основе GeoNames. Совпадающие/близкие города не должны дублироваться под другой транскрипцией. Порция дополнительных городов — 24, загрузка запускается нижним IntersectionObserver. Очередь городов ограничена тремя одновременными задачами. Кнопки догрузки нет.

cityPlaces: определить центр → географические статьи RU/EN и русский поиск → предел близости 10 км → привести к русской записи → строгий отбор → проверить тип и страну через Wikidata P17 → зарегистрировать и опубликовать порцию. Есть кеш памяти и localStorage places-v2:<страна|город> на 24 часа.

Результат не является полным списком достопримечательностей страны. Названия городов справочника могут оставаться латиницей.

## 3. Область карты

placesInBounds сначала публикует места библиотеки внутри bbox. Ниже масштаба 5 сетевой слой не запрашивается. Для внешнего слоя актуальная функция использует geosearch Wikipedia RU/EN, приведение к русским статьям, isDiscoveryPlace и registerPlaces. Итог ограничен 120 точками и границами области.

Photon присутствует в глобальном поиске; объявленная вспомогательная photonArea не означает, что она вызвана действующим placesInBounds.

PlacesMap использует задержку около 220 мс. Конструктор — 280 мс, в browse 180 мс; в full внешняя область не подгружается. Устаревшие запросы отменяются. Программное перемещение к соседней карточке не должно заново формировать набор карточек.

routeMode: только места дня, без внешнего discovery. В редакторе маршрута передаются все дни поездки: их точки и отдельные цветные линии показываются одновременно. Текущий день определяет начальную область и выделение линии. Между днями линия не строится.

## 4. Глобальный поиск

RoutePlaceSearch + usePlaceSearch: локальные совпадения и searchWorld после паузы 350 мс. В интерфейсе поиск начинается с одного символа. searchWorld параллельно использует Photon, Open-Meteo для городов и русскую Wikipedia, затем ранжирует/объединяет результаты. Сеть возвращает до 12 объектов, UI с локальным дополнением — до 16.

Контекст карты влияет на ранжирование, но не превращается в строгий фильтр города. Город — навигационный результат, не достопримечательность маршрута.

## 5. Отбор

isAttraction исключает города, еду, рынки и торговлю, гостиницы и другие неподходящие категории. isDiscoveryPlace для обычных автоматических кандидатов дополнительно требует Wikidata, статью, фото и содержательный русский текст, отсекает ряд станций и случайных локальных объектов. Подготовленные recommended/metadataOrigin проходят отдельную приоритетную ветку.

hasRecommendationCopy принимает авторские/подготовленные записи либо кириллические имя и описание достаточной длины. russianPlaces пытается найти русскую статью по Wikidata. Явный поиск и пользовательские сохранённые маршруты не тождественны автоматическому рекомендательному слою.

## 6. Обогащение

enrichPlaces получает фото/описания, OSM-теги, дополнительные часы и цену через связанные объекты и доступные источники. Используются Wikipedia, Wikidata, Commons, OSM API, Overpass, Wikivoyage и ограниченные подготовленные метаданные. Запросы, тайм-ауты и кеши различаются по источнику; единой гарантии их доступности нет.

Описание очищается от энциклопедического мусора и пустых географических заглушек. Автоматическая LLM-генерация не подключена. Часть вспомогательных форматтеров всё ещё содержит категорийные подсказки; это не равно проверенному авторскому гиду.

placeGallery: связанные изображения статьи → эвристический отбор JPEG/WebP без карт/логотипов/флагов → до шести кандидатов → проверка Commons → только записи со ссылкой и лицензией. photoList объединяет обложку и дополнительные кадры без повторов одного источника. Галереи видимых карточек ограничены двумя параллельными задачами.

## 7. Представление и ошибки

Метаданные: [place-meta.md](place-meta.md). Скелетоны отображаются при загрузке карточек и изображений; после ошибки фото — статичная заглушка. Готовые записи не должны исчезать из-за отказа дополнительного сервиса. Ошибка списка городов не означает доказанное отсутствие городов страны.

Источники текста, цены и фото не взаимозаменяемы. Отсутствие суммы не означает бесплатный вход. Неизвестная лицензия не должна подменяться вымышленной. Исходные авторские материалы и история импортов остаются в docs/sources/.
