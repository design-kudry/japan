# Архитектура

Статическое приложение без серверной базы данных. React 18, Gravity UI UIKit и Date Components, Inter; сборка esbuild.

- `js/trips.js` — маршрутизация по hash, сохранение поездок, каталог городов, подготовка данных.
- `js/gravity-trips.jsx` — создание поездки, основной маршрут, конструктор, карта, переключение поездок.
- `js/trip-segmented-control.jsx` — общий переключатель для создания поездки, расходов и мест.
- `js/trip-expenses.jsx` — расходы, балансы, график.
- `js/travel-pages.jsx` — места, описание места и заметки.
- `css/gravity-trips.css` — оформление интерфейса; `js/fonts.css` — Inter.
- `scripts/build-gravity.mjs` — сборка React и копирование статических ресурсов в dist.
- `image/`, `places/` — изображения и данные мест.

Карта конструктора: MapLibre GL + OpenFreeMap Positron. Если WebGL2 недоступен, используется Leaflet + OpenStreetMap. Карты требуют сети. Фотометки закреплены на координатах; щелчок открывает мини-карточку. Шторка перемещается через Pointer Events, сортировка работает с мышью, касанием и клавиатурой.

В проекте также сохранены HTML-страницы и JS первоначального планировщика Японии. Они используются ссылками старых экранов и не удалены.

Мировой поиск использует Photon, Wikipedia и Open-Meteo Geocoding. Запросы отменяются при смене области или запроса; выборка области кешируется. При недоступности источников показываются ошибки, без подстановки вымышленных результатов. Подробности ниже.

`PlacesMap` разделяет обычную карту и `routeMode`: в режиме маршрута не выполняются внешние поисковые запросы и не добавляются посторонние точки. Общий `EditorMap` обновляет метки отдельно от создания карты, чтобы смена карточки и ответы API не пересоздавали карту.


### Фото и описания мест

`js/place-enrichment.js` загружает теги точных объектов OSM пакетами по типу N/W/R. Использует только явные `wikipedia`, `wikidata`, `wikimedia_commons` связи, без сопоставления фотографий по одному названию. Описание берётся из тегов OSM, описаний Wikidata или вступления связанной статьи Wikipedia. Фото — свободное изображение статьи или связанный файл Commons с данными об авторе и лицензии. Ссылки на статью/файл и авторство выводятся в подробной карточке. Если материала нет, остаются категория, адрес, часы работы; область фотографии сохраняется с заглушкой. Русский язык предпочитается при наличии соответствующей статьи; иначе возможен язык исходной статьи.

Источники запрашиваются с тайм-аутом 10 секунд; максимум 4 параллельных запроса статей, кеш метаданных на 5 минут. Закрытие карты отменяет запросы. Состояние загрузки медиа не управляет положением карты.

Метки `EditorMap` хранятся по постоянному ID: обновление фото/описания не пересоздаёт все маркеры. В «Местах» точки разрежаются по экранному расстоянию 46 px; выбранная точка сохраняется. Движение карты при листании не запускает повторный поиск области. На карте маршрута номера и все маршрутные точки сохраняются.

Проверка обогащения: `./node_modules/.bin/esbuild tests/place-enrichment.test.mjs --bundle --platform=node --format=esm --outfile=/tmp/travel-enrichment.test.mjs`, затем `node --test /tmp/travel-enrichment.test.mjs`.


### Поиск достопримечательностей

`js/use-place-search.js` — общий поиск для карты и конструктора. Запрашивает Photon, координатные статьи Wikipedia на языке запроса и города Open-Meteo; города ограничены типами PPL, достопримечательности ранжируются выше одноимённых населённых пунктов. `js/wiki-places.js` получает координаты, описание и явную связь с файлом статьи. `place-enrichment.js` поддерживает и OSM, и Wiki-объекты. Запросы имеют тайм-аут 8 секунд, устаревшие результаты отменяются. Места с одинаковым Wikidata ID объединяются.

Выборка области (`placesInBounds`): один Photon-запрос по центру видимой области плюс координатные статьи Wikipedia EN/RU внутри bbox; набор объединяется и обрезается границами. Число результатов зависит от данных и доступности источников — это не полный каталог Google. Кафе, рестораны и гостиницы исключены; используются туристические/исторические категории, храмы, парки и природные объекты. Поиск запускается после паузы ~350 мс; выборка карты — ~220 мс (вкладка Места) или ~180–280 мс (конструктор). Актуальная спека: [SERVICE_SPEC.md](./SERVICE_SPEC.md), аудит: [AUDIT.md](./AUDIT.md).

Фото в карточках всегда имеет выделенную область: реальный снимок либо заглушку. В мини-карточках, детальном описании и фотометках используется cover + center, чтобы снимок заполнял круглую или прямоугольную область без белых полей. Переход к найденному месту запускает загрузку новой области, а обычное листание карточек — только перемещение/подсветку. Подборка страны отдаётся частями по мере ответов источников. На карте конструктора точки области видны полупрозрачно рядом с маршрутом; листание карточки, открытой из маршрута, идёт по точкам дня.

Дополнительные проверки: собрать `tests/world-places.test.mjs` esbuild с `--bundle --platform=node --format=esm` и запустить результат через `node --test`.
